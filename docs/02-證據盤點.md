# 02｜證據盤點：多代理到底什麼時候真的比單代理好？

本頁整理**正反兩方的實證證據**。閱讀規則：先看證據等級（A＝有控制變因的對照實驗，B＝生產系統內部評測，C＝案例/觀點），再看結論。

---

## A. 支持「多代理真的贏」的證據

### A1. Anthropic Research 系統（證據等級 B：生產系統內部評測）

出處：[How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)（2025-06）

- **數字**：Lead Opus 4 + Sonnet 4 subagents 的多代理系統，在其內部研究評測上**比單一 Opus 4 高出 90.2%**。
- **為什麼贏**：任務是「廣度優先」——例如「列出 S&P 500 資訊類股所有公司的董事」，需要同時追多條獨立線索，單代理的序列式搜尋會來不及。
- **機制解釋**：多代理的本質是**幫你把 token 花夠**。在 BrowseComp 分析中，token 用量單獨解釋了 80% 的表現變異（加上工具呼叫次數、模型選擇，三者合計 95%）。
- **速度**：平行 spawn 3–5 個 subagent + 平行工具呼叫，複雜查詢時間**最多縮短 90%**。
- **⚠️ 同一篇文章自己給的警語**：
  - 多代理系統消耗的 token **約為聊天的 15 倍**（單代理 agent 約 4 倍）；
  - 「需要所有 agent 共享上下文、或彼此依賴很多的領域，目前不適合多代理」；
  - 「**多數寫程式的任務，真正可平行的部分遠少於研究任務**」；
  - 早期曾出現「簡單查詢就 spawn 50 個 subagent」的失控行為。

**結論**：多代理在「廣度型、可獨立分支、產出可匯總」的高價值任務上有明確收益，但這是**特定任務形狀**的勝利，不是普適優勢。

### A2. Finance Agent 領域（證據等級 A：跨架構對照）

出處：[Capable language models can outgrow the benefits of collaboration](https://www.nature.com/articles/s42256-026-01268-y)（Nature Machine Intelligence, 2026）

- 在 Finance Agent 任務上，**所有多代理架構都大幅贏過單代理（+57% ~ +81%）**。
- 原因：任務結構是「可分解、可獨立驗證的平行分支」（不同標的、不同資料來源）。

### A3. 抽樣式多代理（證據等級 A）

- **More Agents Is All You Need**（TMLR 2024）：同一題平行抽樣多個答案再聚合，效能隨 agent 數提升——但注意這是 **best-of-n 抽樣**，不是「協調式分工」，嚴格說不屬於 swarm 爭議的範圍，常被混為一談。

## B. 支持「單代理更好／多代理優勢被高估」的證據

### B1. 控制算力後，多代理優勢蒸發（證據等級 A）

出處：[Single-Agent LLMs Outperform Multi-Agent Systems on Multi-Hop Reasoning Under Equal Thinking Token Budgets](https://arxiv.org/abs/2604.02460)（arXiv 2604.02460）

- **控制思考 token 預算相同**後，單代理在多跳推理任務上**穩定追平或打贏**多代理。
- 論文的資訊論論證：在固定 token 預算與完美上下文利用下，單代理資訊效率更高（Data Processing Inequality）。
- **關鍵警示**：許多報告的「多代理優勢」其實是**沒被記帳的額外運算**（test-time compute）+ 基準測試的假象，而非架構本身的好處。
- 這正是那則 X 貼文的學術版：*You don't have 200x the compute.*

### B2. 多代理辯論不穩定贏過簡單技巧（證據等級 A）

出處：[Should we be going MAD? A Look at Multi-Agent Debate Strategies for LLMs](https://arxiv.org/abs/2311.17371)

- 系統性比較後發現：多代理辯論（MAD）**目前的形式無法可靠地勝過** self-consistency（同題多次採樣投票）或 multi-path ensembling 等更便宜的策略。
- MAD 對超參數極敏感，難以調優。

### B3. 多代理系統的失敗模式是系統性的（證據等級 A）

出處：[Why Do Multi-Agent LLM Systems Fail?（MAST）](https://arxiv.org/abs/2503.13657)（NeurIPS 2025）

- 1600+ 標註軌跡、7 個 MAS 框架，歸納出 **14 種失敗模式、3 大類**：系統設計缺陷、agent 間失準（misalignment）、任務驗證不足。
- 開宗明義：「**多代理系統在熱門基準上的表現提升通常很小**（often minimal）」。

### B4. 模型越強，多代理的相對優勢越小（證據等級 A）

出處：[Single-agent or Multi-agent Systems? Why Not Both?](https://arxiv.org/abs/2505.18286)（Gao et al. 2025）

- 廣泛實證：**MAS 相對 SAS 的收益隨模型能力提升而遞減**（長上下文、記憶、工具使用進步，把當年催生 MAS 的限制逐一補掉）。
- 提出 hybrid（依題目在 MAS/SAS 間級聯切換）：準確率 +1.1~12%、部署成本最多 −20%。

### B5. 跨領域對照：贏的領域與輸的領域一樣清楚（證據等級 A）

出處：Nature MI 2026（同 A2）

| 任務 | 多代理 vs 單代理 | 任務形狀 |
|---|---|---|
| Finance Agent | **+57% ~ +81%** | 可分解、平行、可獨立驗收 |
| Terminal-Bench | +6%（獨立式）/ **−20%**（集中式） | 工具少，協調不划算 |
| SWE-bench Verified | −1% ~ −13% | 單代理基線已高，序列依賴重 |
| PlanCraft（規劃） | **−39% ~ −70%** | 嚴格序列依賴、動態狀態 |

同一篇的額外發現：
- **協調通訊量隨 agent 數超線性成長**；超過中型團隊規模後，協調效率大幅劣化；
- 3–4 個 agent 以上，單一 agent 的推理品質明顯下滑；
- **沒有任何異質中央化配置打贏同質強模型單代理基線**；
- 「高能力的 sub-agent」比「高能力的 orchestrator」更划算。

### B6. 生產實務派的反對（證據等級 C：觀點＋實務）

- [Don't Build Multi-Agents](https://cognition.ai/blog/dont-build-multi-agents)（Cognition / Devin，2025-06）：拆分任務給 subagent 會**割裂共享上下文**，subagent 看不到彼此的決策，錯誤複製、狀態不一致；主張用 context engineering 讓單一長程 agent 保持完整脈絡。
- [Don't Sleep on Single-agent Systems](https://openhands.dev/blog/dont-sleep-on-single-agent-systems)（OpenHands / Neubig，2024-09）：多 agent 只是在 LLM、prompt、action space 三個變因上換組合，換來的是溝通成本；把一個 agent 變強比養一群弱 agent 有效。

## C. 綜合判讀：證據能支持到什麼程度？

誠實的結論是這樣的（對應討論串的「討論題」性質）：

1. **已站得住腳**：在「可真正平行、分支互相獨立、輸出可低成本匯總、單一 context 裝不下」的任務上，多代理有量化可見的收益（A1、A2、B5 的 Finance Agent 行）。
2. **已站得住腳**：在「固定 token 預算」下，大部分宣稱的多代理優勢會消失（B1、B2）；多數「200 agents」展示屬此類。
3. **已站得住腳**：序列依賴強、需共享狀態的任務（規劃、多數 coding、協作式流程）加 agent 只會變差（B5、A1 警語、B6）。
4. **還沒被證明**：「存在某個單代理絕對做不到、且不是因為單代理沒被給足 token/工具」的案例——這正是原作者想要而討論串尚未交出的東西。
5. **趨勢判斷**：模型越強，需要靠「分身」解決的問題越少（B4）；但「單一 context 裝不下的廣度任務」會長期存在（A1）。

**一句話**：多代理不是「更聰明」，是「花更多 token 換更寬的探索」；值不值得，取決於任務的形狀與單價。
