## 為什麼這則貼文值得學

1. **它戳中了當前 agent 開發的主流迷思**：「agent 數量 = 表現」的堆量思維。貼文的核心論點是：**用量上限（rate limit / quota）是所有 agent 共享的**，平行化不會凭空變出算力，只會把同一份預算切成更多份、再額外燒掉協調用的 token。
2. **它把問題從「能不能做」拉到「有沒有必要」**：多代理能不能做出單代理做不出的東西？能（見 `02-證據盤點.md`）。但「能」不等於「值得」——協調成本可能直接吃掉平行處理的收益。
3. **它是一個很好的架構決策訓練題**：討論串（67 則回覆）裡雙方各自舉案例，剛好可以用來練習「用證據而不是用口號選架構」。本站的 `04-決策框架.md` 就是為這個討論題準備的評分工具。
