# 多代理 vs 單代理：哪些工作真的比單代理好？

> 繁體中文深度研究 + 學習資料 + 範本網站  
> 議題來源：[X 貼文 #2110116906581848217](https://x.com/i/web/status/2110116906581848217)（Martin @cantcomputer，2026-10-13）

**🌐 範本網站**：https://tboydar.github.io/multi-agent-vs-single-agent-zh/

## 這是什麼

原作者公開徵求「agent swarm 做得到、單一 agent 做不到」的案例，並嘲諷「200 個平行 agent 擠在同一份訂閱額度」的展示文化。這是**討論題，不是已證實的結論**。

本專案把討論題升級成可學習的材料：

- **證據盤點**：正反兩方的實證研究（哪些贏、贏多少、控制變因後還剩多少）；
- **協調成本解剖**：token、rate limit、上下文割裂、同步瓶頸四種成本的算法；
- **決策框架**：五問評分表 + 一票否決，直接回答「Discord 任務分派要不要開代理群」（答案：不需要，評分 3/10）；
- **可複製範本**：單代理、主管–工人、扇出閘門的 prompt 與判定程式碼。

## 核心結論（誠實版）

1. **多代理真正贏的條件很窄**：分支可獨立執行、輸出可低成本匯總、資料量超過單一 context——三者同時成立才有量化收益（如廣度型研究：Anthropic 內部評測 +90.2%）。
2. **控制算力後優勢大幅縮水**：同 token 預算下，單代理在多跳推理追平或勝出；多代理辯論也打不過 self-consistency。
3. **序列依賴任務會變差**：規劃類任務多代理 −39%~−70%，多數 coding 任務單代理基線已高。
4. **共享額度是硬約束**：多代理 token 約為聊天 15×；agent 不會憑空變出算力，只會排隊搶同一條水管。
5. **模型越強，分身的價值越小**，但 context 裝不下的廣度任務會長期存在。
