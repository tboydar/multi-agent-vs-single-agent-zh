§ 01 · EVIDENCE

證據盤點：多代理到底什麼時候真的比單代理好？

閱讀規則：先看證據等級，再看結論。A＝有控制變因的對照實驗 · B＝生產系統內部評測 · C＝案例或觀點。

§ 01A

支持「多代理真的贏」

PRO
A1

Anthropic Research 系統：+90.2%anthropic.com · 2025-06 · B

Lead Opus 4 + Sonnet 4 subagents 在其內部研究評測上比單一 Opus 4 高出 90.2%。任務形狀是「廣度優先」——例如列出 S&P 500 資訊類股所有公司的董事，需同時追多條獨立線索，單代理的序列式搜尋來不及。

機制：多代理的本質是幫你把 token 花夠。BrowseComp 分析中 token 用量單獨解釋 80% 的表現變異（加工具次數與模型選擇合計 95%）。平行化讓複雜查詢時間最多縮短 90%。

同篇文章的警語：多代理 token 約為聊天 15×；「需要共享上下文或彼此依賴多的領域不適合」；「多數寫程式的可平行部分遠少於研究」；早期曾發生「簡單查詢就 spawn 50 個 subagent」的失控。

A2

Finance Agent：+57% ~ +81%Nature Machine Intelligence 2026 · A

跨架構對照中，Finance Agent 是多代理全面大勝的領域：所有多代理架構都大幅贏過單代理。任務形狀：可分解、平行、每個分支（不同標的、不同資料源）可獨立驗收。

這是「多代理勝出需要的條件同時成立」的最佳正面案例。

A3

抽樣式多代理（best-of-n）TMLR 2024 · A

「More Agents Is All You Need」：同一題平行抽樣多個答案再聚合，效能隨 agent 數提升。

但這是抽樣不是分工——沒有交接成本，常被拿來替「協調式 swarm」背書，屬於混用概念。

§ 01B

支持「單代理更好／優勢被高估」

CON
B1

控制算力後，優勢蒸發arXiv 2604.02460 · A

控制思考 token 預算相同後，單代理在多跳推理任務上穩定追平或打贏多代理。資訊論論證：固定預算下單代理資訊效率更高。

許多報告的「多代理優勢」其實是沒被記帳的額外運算與基準測試假象——這正是 X 貼文的學術版：“You don't have 200x the compute.”

B2

多代理辯論打不過便宜技巧arXiv 2311.17371 · A

系統性比較：多代理辯論（MAD）目前的形式無法可靠勝過 self-consistency（同題多次投票）或 multi-path ensembling；且對超參數極敏感、難調優。

想提升正確率，先用便宜的抽樣投票，再考慮養 agent 群。

B3

失敗模式是系統性的（MAST）arXiv 2503.13657 · NeurIPS 2025 · A

1600+ 標註軌跡、7 個 MAS 框架，歸納 14 種失敗模式、3 大類：系統設計缺陷、agent 間失準、任務驗證不足。開宗明義：MAS 在熱門基準上的提升「通常很小」。

多代理把「一條軌跡的錯誤」變成「N 條軌跡的對帳問題」。

B4

模型越強，分身價值越小arXiv 2505.18286 · Gao et al. 2025 · A

廣泛實證：MAS 相對 SAS 的收益隨模型能力提升而遞減——長上下文、記憶、工具使用進步，把當年催生 MAS 的限制逐一補掉。提出的 hybrid 級聯：+1.1~12% 準確率、−20% 成本。

今天的架構決策要預留「模型升級後重新評估」的鉤子。

B5

跨領域對照：贏輸一樣清楚Nature MI 2026 · A

任務多代理 vs 單代理任務形狀
Finance Agent+57% ~ +81%可分解、平行、可獨立驗收
Terminal-Bench+6% / −20%工具少，協調不划算（集中式變差）
SWE-bench Verified−1% ~ −13%單代理基線已高、序列依賴重
PlanCraft（規劃）−39% ~ −70%嚴格序列依賴、動態狀態

附加發現：協調通訊量隨 agent 數超線性成長；3–4 個 agent 以上單分支推理品質明顯下滑；沒有任何異質中央化配置打贏同質強模型單代理基線；「高能力 sub-agent」比「高能力 orchestrator」划算。

B6

生產實務派的反對Cognition · OpenHands · C

Don't Build Multi-Agents（Cognition/Devin）：拆分給 subagent 會割裂共享上下文，subagent 看不到彼此決策，導致錯誤複製與狀態不一致；主張用 context engineering 維持單一長程 agent 的完整脈絡。

Don't Sleep on Single-agent Systems（OpenHands）：多 agent 只是在 LLM、prompt、action space 三個變因上換組合，換來的是溝通成本；把一個 agent 變強比養一群弱 agent 有效。

§ 01C

綜合判讀：證據能支持到什麼程度？

SYNTHESIS
說法目前證據是否支持
可真正平行、獨立分支、context 裝不下的任務，多代理有量化收益✔ 支持（A1、A2、B5 正面行）
固定 token 預算下，多代理仍普遍更強✘ 不支持（B1、B2：優勢消失）
序列依賴、共享狀態的任務加 agent 會變好✘ 反證明確（B5、A1 警語、B6）
存在「單代理絕對做不到」的案例（原作者所求）？尚未有人交出可量測版本
模型越強，多代理的相對優勢越小✔ 支持（B4）
給討論串的一句話

多代理不是「更聰明」，是「花更多 token 換更寬的探索」。原作者要的證據標準（排除算力差異後的純架構優勢）尚未被滿足——這就是為什麼它是討論題。
