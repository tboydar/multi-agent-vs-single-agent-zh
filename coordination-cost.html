§ 02 · COORDINATION COST

協調成本解剖：
平行處理的收益去哪了？

那則 X 貼文的技術核心只有一句：平行化不會增加你的預算，只會增加你的開銷。本頁把「開銷」拆開算給你看。

§ 02A

四種協調成本

4 COSTS
COST 01 · TOKEN

Token 成本

一般聊天 1× → 單一 agent ~4× → 多代理 ~15×（Anthropic 生產數據）。多出來的不是工作，是任務描述、狀態回報、中間轉述、匯總重試。

分支輸出小、交接對話長時，交接成本可能大於工作本身。

COST 02 · RATE LIMIT

用量上限

所有 agent 共享同一份訂閱額度與 API 限流。200 個 agent 不是 200 倍算力，是同一條水管被切成 200 股。

瓶頸從「想不完」變成「集體排隊」；一個分支撞限流，匯總端全體等待。

COST 03 · CONTEXT

上下文割裂

subagent 彼此看不到決策，只能透過「任務描述」這條窄管溝通；描述寫得含糊 → 重複工作、漏東漏西。

匯總端只拿到被壓縮兩次的結論，原始脈絡已丟失。

COST 04 · SYNC & VERIFY

同步與驗證

同步匯總：一個慢分支拖住全隊（Anthropic 的 lead agent 同步等待每批 subagent）。

驗證責任轉移：要先分辨哪條軌跡錯了；補查重試使成本非線性放大。

相對嚴重度為教學示意，實際比例依任務而異；token 倍數為 Anthropic 公布的生產數據。

§ 02B

收益什麼時候蓋過成本？

FIVE CONDITIONS
# 多代理成本速算
多代理總成本 ≈ Σ(各分支獨立工作 token) + 交接 token × 分支數²
                     ↑ 實際收益來自這裡        ↑ 協調稅，隨分支數快速長大

# 平行收益成立，需要同時滿足（缺一容易翻車）
1. 分支真正獨立（不需即時交換狀態）
2. 分支數 × 單分支工作量 > 交接成本   # 小任務開分支是負資產
3. 匯總便宜（N 份結論合成 1 份 < 重做一遍）
4. 資料量超過單一 context             # 多 context 是為了「裝更多」不是「更聰明」
5. 任務價值付得起 10–15× token        # Anthropic: economic viability
quota-bound vs latency-bound

如果你的系統受固定額度限制（quota-bound）而非受思考時間限制，增加 agent 數通常只會把等待從「串行」變成「擁塞」。X 貼文的 200 agents 就是 quota-bound 系統硬加平行的反例。

§ 02C

心智模型：兩種系統的瓶頸位置

DIAGRAM
單代理：  [思考→行動→思考→行動] ...... → 結果
          成本 = 工作本身；瓶頸 = 速度（序列）

多代理：  [主管 分派]
            ├─ [agent A 獨立工作] ─┐
            ├─ [agent B 獨立工作] ─┼─ [匯總] → 結果
            └─ [agent C 獨立工作] ─┘
          成本 = 工作本身 + 分派 + 交接 + 匯總 + 排隊
          瓶頸 = 匯總端 + 共享額度

→ 分支獨立且夠肥：成本差距被時間／覆蓋率補回來
→ 分支互相依賴或很瘦：協調稅直接吃掉全部收益

對應到 X 貼文

  • 「200 agents competing for usage limits」＝ COST 02
  • 「burning tokens coordinating」＝ COST 01 + 04
  • 作者要的案例 = 右欄五條件同時成立、且排除算力差異

反過來，什麼情況下該用多代理

  • 200 家公司的平行調查（context 裝不下）
  • 多來源的新聞／輿情廣度掃描（分支獨立）
  • 每分支可回傳結構化欄位、機器可合併（匯總便宜）
